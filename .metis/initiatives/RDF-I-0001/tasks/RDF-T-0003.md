# Clone, intern, and destroy operations

## Parent Initiative

[[RDF-I-0001]]

## Objective

Implement the ownership operations that promote borrowed terms to owned — `clone`, interning, and `destroy` — per RDF-A-0001's borrow/clone contract and the initiative's stdlib allocator conventions.

## Acceptance Criteria

## Acceptance Criteria

- [x] `clone` for `Term`, `Triple`, and `Quad` with a trailing `allocator := context.allocator` parameter, deep-copying all strings and recursing through `^Triple` triple terms.
- [x] `destroy` mirrors `clone` exactly, freeing only what `clone` allocated; safe on borrowed (never-cloned) values is documented as a non-goal or handled explicitly — decide and document. **Decision: programming error / undefined behavior, documented on the `destroy` proc group.**
- [x] Intern table: maps lexical content to a stable owned string, returning the same backing storage for repeated inputs; interning a term yields an owned term whose strings live in the table.
- [x] A cloned statement remains valid and `equal` to its original after the source buffer is overwritten (test overwrites the buffer to prove independence).
- [x] Tracking allocator shows zero leaks across clone → destroy round trips, including nested triple terms, and across intern-table destroy.

## Implementation Notes

### Technical Approach
These are the only allocating operations in the core package. Recursive clone/destroy for triple terms must agree on ownership of the pointed-to `Triple` (clone allocates it; destroy frees it).

### Dependencies
RDF-T-0002 (complete type set including `Quad`).

## Status Updates

**2026-08-04**: Implemented in `rdf/clone.odin` (`clone`/`destroy` proc groups over `Term`, `Triple`, `Quad`, and `Graph_Label`) and `rdf/intern.odin` (`Intern_Table` with `intern`, `intern_term`, `intern_triple`, `intern_quad`). Decisions made during implementation:

- `destroy` on a borrowed (never-cloned) value, or with a mismatched allocator, is a **programming error with undefined behavior** — documented on the proc group. Ownership stays a contract, not tracked state.
- `Graph_Label` got its own clone/destroy overloads (a quad's graph name needs the same treatment as its terms).
- The intern table stores each distinct string once as both map key and value, and additionally owns triple-term nodes in a `[dynamic]^Triple` so `intern_table_destroy` can free them — interned terms' pointed-to triples live in the table, mirroring how their strings do.
- Vocabulary constants get cloned like any other string when a statement is cloned; no special-casing of static strings (uniform ownership beats a micro-optimization).

Tests in `rdf/ownership_test.odin`: buffer-overwrite independence (clone survives, borrowed original visibly corrupts), tracking-allocator leak checks for clone→destroy with a nested triple term and for the intern table, and backing-storage identity for interned repeats (`raw_data` pointer equality). 8/8 package tests pass; `odin check -vet -strict-style` clean.
