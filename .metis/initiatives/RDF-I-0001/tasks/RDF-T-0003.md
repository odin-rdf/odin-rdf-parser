# Clone, intern, and destroy operations

## Parent Initiative

[[RDF-I-0001]]

## Objective

Implement the ownership operations that promote borrowed terms to owned — `clone`, interning, and `destroy` — per RDF-A-0001's borrow/clone contract and the initiative's stdlib allocator conventions.

## Acceptance Criteria

- [ ] `clone` for `Term`, `Triple`, and `Quad` with a trailing `allocator := context.allocator` parameter, deep-copying all strings and recursing through `^Triple` triple terms.
- [ ] `destroy` mirrors `clone` exactly, freeing only what `clone` allocated; safe on borrowed (never-cloned) values is documented as a non-goal or handled explicitly — decide and document.
- [ ] Intern table: maps lexical content to a stable owned string, returning the same backing storage for repeated inputs; interning a term yields an owned term whose strings live in the table.
- [ ] A cloned statement remains valid and `equal` to its original after the source buffer is overwritten (test overwrites the buffer to prove independence).
- [ ] Tracking allocator shows zero leaks across clone → destroy round trips, including nested triple terms, and across intern-table destroy.

## Implementation Notes

### Technical Approach
These are the only allocating operations in the core package. Recursive clone/destroy for triple terms must agree on ownership of the pointed-to `Triple` (clone allocates it; destroy frees it).

### Dependencies
RDF-T-0002 (complete type set including `Quad`).
