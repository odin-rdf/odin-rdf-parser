# Equality and hashing proc groups

## Parent Initiative

[[RDF-I-0001]]

## Objective

Implement structural equality and hashing as overloaded proc groups (`rdf.equal`, `rdf.hash`) over directly-callable per-type procedures, with the semantics fixed by ADR RDF-A-0002.

## Acceptance Criteria

## Acceptance Criteria

- [x] Per-type procedures for `Term`, `Triple`, `Quad` (and `Graph_Label`), collected into `equal` and `hash` proc groups.
- [x] Equality is structural and buffer-independent: identical content borrowed from different buffers compares equal; verified by a test using two separate buffers.
- [x] Equality and hashing recurse through nested triple terms; `Graph_Label` participates in quad equality with `nil` (default graph) handled correctly.
- [x] Hashing uses FNV-1a from `core:hash`, isolated behind one internal procedure so the function can be swapped without any public API change.
- [x] Property exercised in tests: `equal(a, b)` implies `hash(a) == hash(b)`, including literal corner cases (same lexical, different datatype/language/direction must differ).

## Implementation Notes

### Technical Approach
Hash the variant tag plus each component's bytes; for literals include datatype, language, and direction so the RDF 1.2 distinctions are honored. No allocation anywhere in equality or hashing.

### Dependencies
RDF-T-0002 (complete type set). Independent of RDF-T-0003 — can proceed in parallel.

## Status Updates

**2026-08-04**: Implemented in `rdf/equal.odin` and `rdf/hash.odin`. Notes:

- `equal` differs from built-in `==` only for triple terms (`==` compares pointers; `equal` compares structure with a same-pointer fast path) — stated in the doc comment since it's the one subtlety consumers must know.
- Hashing chains FNV-1a (`core:hash.fnv64a`, which takes a seed) through variant tags and components. Each string is prefixed by its length so adjacent components can't collide by shifting bytes across their boundary; literals mix in datatype, language, and direction. `hash_bytes` is the single swap point for the function.
- Nil handling: nil `Term`/`Graph_Label` (default graph) equal only to nil, hashed with tag 0; a nil `^Triple` variant pointer is guarded rather than dereferenced.
- No allocation anywhere in equality or hashing.

Tests in `rdf/equality_test.odin`: two-buffer independence, kind confusion (IRI vs blank node, same label), literal corner cases (plain/tagged/directed/typed all mutually unequal with distinct hashes), triple-term structural recursion (including the `==`-vs-`equal` difference and a one-level-down mutation), and quad graph-label cases (default vs named vs blank-node graph). 12/12 package tests pass; `odin check -vet -strict-style` clean.
