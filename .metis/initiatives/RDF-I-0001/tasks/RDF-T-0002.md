# Triple, quad, and graph label types with vocabulary constants

## Parent Initiative

[[RDF-I-0001]]

## Objective

Complete the statement-level model: `Graph_Label`, `Quad`, constructors that enforce the literal invariants, and the vocabulary constants the model needs.

## Acceptance Criteria

## Acceptance Criteria

- [x] `Graph_Label :: union { IRI, Blank_Node }` defined, with `nil` documented as the default graph.
- [x] `Quad` embeds `Triple` via `using`; a `Quad` is usable wherever a `Triple` is expected.
- [x] Literal constructors cover the three cases — plain (datatype defaults to `xsd:string`), language-tagged (datatype forced to `rdf:langString`), and directional language-tagged (datatype forced to `rdf:dirLangString`, direction required) — so invariant-violating literals cannot be built through the public constructors.
- [x] Vocabulary constants defined for the IRIs the model itself needs: `xsd:string`, `rdf:langString`, `rdf:dirLangString`, plus an agreed minimal set of common terms (e.g., `rdf:type`, `rdf:nil`).
- [x] Constructors for non-star terms perform no allocation; `odin check` and smoke tests pass.

## Implementation Notes

### Technical Approach
Constructors enforce what the type system cannot (per RDF-A-0002's "constructors over type-level invariants"). Keep the vocabulary minimal — full vocabulary packages are downstream concerns.

### Dependencies
RDF-T-0001 (core term types).

## Status Updates

**2026-08-04**: Implemented across three files: `rdf/quads.odin` (`Graph_Label` union with `nil` = default graph; `Quad` embedding `Triple` via `using`), `rdf/vocab.odin` (namespace constants plus `XSD_STRING`, `RDF_LANG_STRING`, `RDF_DIR_LANG_STRING`, `RDF_TYPE`, `RDF_NIL`, `RDF_FIRST`, `RDF_REST`, `RDF_REIFIES` — first/rest for Turtle collections, reifies for RDF 1.2 reification), and `rdf/literals.odin` (constructors with asserts enforcing the literal invariants).

**Design deviation worth knowing**: the `literal` proc group covers plain/lang/dir-lang only. `literal_typed` had to stay out of the group — an untyped string argument matches both `string` and `IRI` (distinct string does not win overload resolution against untyped constants), making `literal("x", "en")` ambiguous. Typed literals are built with an explicit `literal_typed(lexical, datatype)` call. Documented in the group's doc comment.

Smoke tests in `rdf/model_test.odin` (constructors, `using` embedding, nil default graph, triple-term nesting): 4/4 pass under `odin test` with memory tracking; `odin check -vet -strict-style` clean. Task complete.
