# Triple, quad, and graph label types with vocabulary constants

## Parent Initiative

[[RDF-I-0001]]

## Objective

Complete the statement-level model: `Graph_Label`, `Quad`, constructors that enforce the literal invariants, and the vocabulary constants the model needs.

## Acceptance Criteria

- [ ] `Graph_Label :: union { IRI, Blank_Node }` defined, with `nil` documented as the default graph.
- [ ] `Quad` embeds `Triple` via `using`; a `Quad` is usable wherever a `Triple` is expected.
- [ ] Literal constructors cover the three cases — plain (datatype defaults to `xsd:string`), language-tagged (datatype forced to `rdf:langString`), and directional language-tagged (datatype forced to `rdf:dirLangString`, direction required) — so invariant-violating literals cannot be built through the public constructors.
- [ ] Vocabulary constants defined for the IRIs the model itself needs: `xsd:string`, `rdf:langString`, `rdf:dirLangString`, plus an agreed minimal set of common terms (e.g., `rdf:type`, `rdf:nil`).
- [ ] Constructors for non-star terms perform no allocation; `odin check` and smoke tests pass.

## Implementation Notes

### Technical Approach
Constructors enforce what the type system cannot (per RDF-A-0002's "constructors over type-level invariants"). Keep the vocabulary minimal — full vocabulary packages are downstream concerns.

### Dependencies
RDF-T-0001 (core term types).
