# Turtle parser RDF 1.2 star surface

## Parent Initiative

[[RDF-I-0003]]

## Objective

Implement the full RDF 1.2 star surface in the Turtle parser: triple terms (`<<( )>>`), reified triples (`<< >>`), annotation blocks (`{| |}`), and the reifier syntax (`~`), producing the same triple-term representation the line-based parsers already use — per the approved suite-driven scope decision.

## Acceptance Criteria

## Acceptance Criteria

- [ ] Triple terms `<<( s p o )>>` parse in object position and nest, yielding the existing triple-term representation from the core data model.
- [ ] Reified triples `<< s p o >>` (with and without explicit `~ reifier`) expand to the spec-mandated `rdf:reifies` triples with correctly synthesized or explicit reifier terms.
- [ ] Annotation blocks `{| ... |}` after an object expand per spec, supporting full predicate/object-list syntax inside the block, including nested annotations.
- [ ] Standalone reifier syntax on subjects/objects handled everywhere the RDF 1.2 grammar permits it.
- [ ] Constructs in the published grammar that the vendored W3C 1.2 suite does not exercise still parse; each is listed in Status Updates flagged as untested-by-suite (per the approved scope decision).
- [ ] Unit tests per construct, nesting combinations with [[RDF-T-0015]] structures (annotation inside property list, triple term in collection), and error cases (triple term in subject position, malformed annotation).

## Implementation Notes

### Technical Approach

Extends the recursive-descent productions and reuses the statement queue for reification/annotation fan-out. Reifier synthesis uses the same anonymous-label scheme as property lists. Cross-check the expansion rules against what the N-Triples 1.2 parser produces for triple terms so both paths intern identical representations.

### Dependencies

[[RDF-T-0015]] (structures and statement queue).

### Risk Considerations

The RDF 1.2 annotation/reifier expansion rules are the newest and least-implemented part of the spec — transcribe from the current W3C draft the suites are pinned to, and record the spec revision in Status Updates. Grammar ambiguity between `<<` and `<<(` needs two-byte lookahead in the scanner (coordinate with [[RDF-T-0012]] if not already handled).
