# Vendor W3C Turtle/TriG suites with eval-test comparison

## Parent Initiative

[[RDF-I-0003]]

## Objective

Vendor the official W3C Turtle and TriG test suites (RDF 1.1 and RDF 1.2), extend the `tests/w3c` harness with eval-test comparison, and reach a 100% pass rate — the initiative's conformance gate.

## Acceptance Criteria

## Acceptance Criteria

- [ ] Turtle and TriG suites (1.1 + 1.2) vendored under `tests/w3c` with provenance recorded (source URL and revision), same layout as the existing N-Triples/N-Quads suites.
- [ ] Harness runs all four test types: positive syntax, negative syntax, positive eval, negative eval — reusing the existing format-agnostic runner.
- [ ] Eval comparison implemented: expected `.nt`/`.nq` files parsed with the RDF-I-0002 parsers, actual output compared with deterministic blank-node label mapping; if suite inspection shows tests requiring full isomorphism, escalate and record the evidence (test names) in Status Updates — otherwise record why deterministic mapping suffices.
- [ ] Eval tests apply the manifest-specified base IRI when resolving relative IRIs in test inputs.
- [ ] 100% pass on all vendored Turtle and TriG suites; per-suite counts recorded in Status Updates (as RDF-T-0010 did).
- [ ] RDF 1.2 constructs the suites exercise are cross-checked against the [[RDF-T-0016]] untested-by-suite list, and that list updated.

## Implementation Notes

### Technical Approach

Suite bring-up is diagnostic-driven: run, triage failures into parser bugs vs harness gaps vs suite-interpretation questions, log the triage in Status Updates as the pass rate climbs. The blank-node comparison should live in the harness as a graph-compare helper so [[RDF-T-0018]] round-trip tests can reuse it.

### Dependencies

[[RDF-T-0016]] (Turtle complete), [[RDF-T-0017]] (TriG). The manifest reader is still the hand-rolled one at this point — replacing it is [[RDF-T-0020]], sequenced after so bring-up isn't blocked on it.

### Risk Considerations

Eval tests are the first place parser-internal choices (label synthesis, emission order) meet externally-fixed expectations — expect the deterministic-mapping assumption to be stress-tested. If more than a handful of tests need true isomorphism, implement the standard refinement algorithm rather than special-casing.

## Status Updates

**2026-08-04 — Completed. 100% pass on all 10 vendored suites: 1045 conformance tests.**

Per-suite counts: rdf11-ntriples 70/70, rdf11-nquads 87/87, rdf12-ntriples-syntax 29/29, rdf12-nquads-syntax 27/27, **rdf11-turtle 313/313, rdf11-trig 356/356, rdf12-turtle-syntax 74/74, rdf12-turtle-eval 29/29, rdf12-trig-syntax 35/35, rdf12-trig-eval 25/25**. Six new suites vendored from the same pinned commit (`767554e1…`) as the line-based ones; README provenance table extended.

**Isomorphism decision — escalated, with evidence**: deterministic first-occurrence label mapping was never sound because expected files are unordered, and `turtle12-eval-annotation-07` additionally requires SET semantics (its action asserts `:s :p :o` twice; the expected graph has it once). Implemented in `harness/compare.odin`: dedupe by exact serialization, then backtracking bijection over statements grouped by blank-masked skeleton keys — ground statements never branch, so it's effectively linear on real suite data.

**Bring-up triage — four parser bugs found and fixed** (all now unit-covered by the suites):
1. UCHAR escapes accepting surrogates (`\ud800`) and codepoints > U+10FFFF — now rejected everywhere (`scan_hex`).
2. UCHAR in IRIREF decoding to forbidden IRI characters (`>` = `>`) — now rejected.
3. Long strings closed at the LAST run of 3+ quotes; the grammar closes at the FIRST (`"""abc""""@en` must fail — W3C bad-string-06/07). Scanner test updated to the correct rule.
4. A validly encoded U+FFFD decodes as `utf8.RUNE_ERROR` with size 3 and is legal `PN_CHARS_BASE` — the size-1 check now distinguishes it from invalid bytes (PN_CHARS_BASE boundary tests).

**[[RDF-T-0016]] cross-check**: the `VERSION`/`@version` directive WAS exercised (turtle12-version-01..08 + 6 negative) — implemented during this task (case-insensitive bare form, `@version … .` form, short-string specifier only, value discarded; `Token.long_string` added to enforce the short-form rule). With that, no grammar surface in the pinned suites is unimplemented; remaining untested-by-suite surface is only exotic combinations (e.g. annotation blocks on objects inside annotation blocks), which parse via the same productions.

Harness base-IRI convention verified: `mf:assumedTestBase` + action file name, applied to both syntax and eval runs.
