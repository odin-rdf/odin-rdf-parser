# Turtle parser structures: lists, property lists, collections, literals

## Parent Initiative

[[RDF-I-0003]]

## Objective

Extend the Turtle parser with the nested/fan-out grammar: predicate lists (`;`), object lists (`,`), blank node property lists (`[ ]`), collections (`( )`), long strings, and numeric/boolean literals — including the statement queue that lets `parser_next` yield one triple at a time from multi-triple statements.

## Acceptance Criteria

## Acceptance Criteria

- [ ] Predicate lists and object lists produce triples in document order, including stray-`;` tolerance where the grammar allows it.
- [ ] Blank node property lists synthesize anonymous nodes via the [[RDF-T-0014]] label scheme, usable in subject and object position, arbitrarily nested.
- [ ] Collections expand to `rdf:first`/`rdf:rest` chains terminated by `rdf:nil`; empty `()` yields `rdf:nil` as a term with no triples; nested collections and property lists inside collections work.
- [ ] Statement queue implemented per the initiative design: growable, owned by the parser, reset (not freed) per top-level statement; allocation guard proves `parser_next` allocates nothing in steady state once the queue has grown to the document's high-water mark.
- [ ] Long strings (`"""`/`'''`) with embedded quotes and newlines; line/column tracking stays correct across them.
- [ ] Numeric literals captured lexically with `xsd:integer`/`xsd:decimal`/`xsd:double` datatype IRIs; `true`/`false` with `xsd:boolean` — no value evaluation.
- [ ] Deep nesting produces a structured error at a documented recursion bound, not a stack overflow.
- [ ] Unit tests for each structure, nesting combinations, and error paths.

## Implementation Notes

### Technical Approach

Recursive-descent productions append to the statement queue; `parser_next` drains it before scanning the next top-level statement. Triple emission order follows the spec's fan-out semantics (property-list triples emitted where the anonymous node appears). Recursion bound implemented as an explicit depth counter shared by the `[ ]`/`( )`/embedded-triple productions.

### Dependencies

[[RDF-T-0014]] (parser core).

### Risk Considerations

Emission order matters for eval-test debuggability even though graph semantics don't require it — keep it deterministic and documented. The queue's memory discipline is the initiative's main new allocation surface; guard-test it here, not in [[RDF-T-0021]].
