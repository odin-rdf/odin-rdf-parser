# RFC 3986 relative IRI resolution

## Parent Initiative

[[RDF-I-0003]]

## Objective

Implement RFC 3986 section 5 reference resolution (merge paths + remove_dot_segments) as an internal package resolving relative IRI references against a base IRI, allocating resolved results from the caller-supplied intern table — implemented once, used by both the Turtle and TriG parsers.

## Acceptance Criteria

## Acceptance Criteria

- [ ] Passes the full RFC 3986 §5.4 example sets, both normal and abnormal (`../../g`, `./../g`, `g;x=1/../y`, dot-segment excess, etc.).
- [ ] Handles the reference classes: absolute IRI (passes through), network-path (`//host/x`), absolute-path, relative-path, empty reference, and fragment-only (`#frag`) references.
- [ ] Chained base updates resolve correctly: each `@base`/`BASE` directive resolves against the base in effect at that point.
- [ ] Resolution is lexical byte-level only — no percent-decoding or case normalization, consistent with the initiative's scheme-level-validation non-goal.
- [ ] Resolved IRIs are allocated from the intern table; allocation guard confirms at most one allocation per distinct resolved IRI and zero for repeat resolutions of the same reference against the same base.
- [ ] Unit tests cover the reference classes, §5.4 sets, and base-chaining.

## Implementation Notes

### Technical Approach

Straight transcription of RFC 3986 §5.2 (transform references) and §5.2.4 (remove_dot_segments), operating on byte slices. Build the resolved IRI into a scratch buffer, then intern the result — the scratch buffer is reusable parser state, so steady-state resolution costs only intern-table lookups.

### Dependencies

The intern table from the core data model (RDF-I-0001). Independent of [[RDF-T-0012]] — can proceed in parallel.

### Risk Considerations

The abnormal-example set exists because implementations get dot-segment handling wrong; transcribe the algorithm literally rather than optimizing it. Base IRIs without authority or path components need the merge-path edge cases tested.

## Status Updates

**2026-08-04 — Completed.** New package `rdf/internal/iri` (`resolve.odin`, `resolve_test.odin`); 5 tests pass covering both full §5.4 example sets, reference classes, base-chaining, and the repeat-resolution allocation guard.

- `parse` splits per appendix B (total — cannot fail; garbage lands in the path); `resolve` is the §5.2.2 strict transform; `remove_dot_segments` is a literal §5.2.4 transcription.
- **One bug found by the §5.4 suite during implementation**: running dot-removal over only the reference path after pre-appending the merged base prefix lets leading `../` strip without popping base segments. Fixed by feeding the whole merged path through the algorithm as one input — this is why the task insisted on literal transcription.
- Scratch is a two-buffer struct (`merged` + `out`), caller-owned, capacity-retained; result interned. Guard asserts zero allocations across 100 repeat passes.
- Contract for [[RDF-T-0014]]: `ok=false` iff ref is relative and base has no scheme — map to the `.Relative_IRI` error (no `@base` established). Every base the parser stores comes back from `resolve`, so bases are always dot-normalized.
