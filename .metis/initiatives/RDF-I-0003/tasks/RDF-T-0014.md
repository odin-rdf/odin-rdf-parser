# Turtle parser core: directives, terms, simple triples

## Parent Initiative

[[RDF-I-0003]]

## Objective

Implement the `rdf/turtle` package's parser core over the scanner: `@prefix`/`@base` and SPARQL-style `PREFIX`/`BASE` directives, prefixed-name expansion through the intern table, relative IRI resolution, and simple `subject predicate object .` triples with IRIs, blank node labels, the `a` keyword, and literals in the simple string forms — establishing the public API idiom and the parser-state/lifetime architecture everything later builds on.

## Acceptance Criteria

## Acceptance Criteria

- [ ] Public API matches the line-based packages: `parser_init`/`parser_next`/`parser_destroy`, sticky structured errors with line/column, per-statement validity contract.
- [ ] All four directive forms parsed, including case-insensitive `PREFIX`/`BASE` without trailing `.`; later `@prefix` for the same prefix overrides the earlier binding; undefined prefix on use is a structured error.
- [ ] Prefixed names concatenate namespace + unescaped local part and intern the result — one materialization per distinct IRI per parse, owned by the parser's intern table for the parser's lifetime (boundary with per-statement CoW unescapes documented in the package doc comment).
- [ ] Relative IRIs (in `IRIREF` and after expansion where applicable) resolve via [[RDF-T-0013]] against the current base.
- [ ] Document blank-node labels are preserved; the synthesized-label scheme (deterministic counter, collision remapping of document labels per the initiative design) is implemented here even though `[ ]` arrives in [[RDF-T-0015]].
- [ ] Literals: short single/double-quoted strings with escapes (CoW), language tags with RDF 1.2 base direction, `^^` datatypes.
- [ ] Unit tests for every production and error path (bad directive, undefined prefix, bad escape in local part, unterminated statement).

## Implementation Notes

### Technical Approach

Recursive descent over the [[RDF-T-0012]] token stream, mirroring the statement-core structure from `rdf/internal/statement` where it fits. Parser state: prefix map (byte-slice keys into interned namespace IRIs), current base, intern table, scratch buffers. `PN_LOCAL` escape stripping happens at expansion time into the scratch buffer before interning.

### Dependencies

[[RDF-T-0012]] (scanner), [[RDF-T-0013]] (IRI resolution). Blocks everything downstream.

### Risk Considerations

The intern-lifetime vs per-statement-free boundary is the architectural heart of this initiative — get it precisely documented and guard-tested here, or every later task inherits ambiguity. Prefix map keys must remain valid across statements; decide between copying prefix strings and interning them too.

## Status Updates

**2026-08-04 — Completed.** Parser core in `rdf/internal/ttl/parser.odin`, public layer in `rdf/turtle/parser.odin`; 12 tests pass, full repo suite green.

- **Architecture note**: the core went into `rdf/internal/ttl` (with the scanner) from the start, with `rdf/turtle` as a thin `using core` wrapper — pre-empting the refactor [[RDF-T-0017]] planned, so TriG can be a second thin layer.
- **Lifetime boundary implemented and documented** (ttl package doc): intern table owns prefix expansions, resolved IRIs, and synthesized/remapped labels for the parser's lifetime; CoW string unescapes and document labels are per-statement; the statement queue resets (capacity retained) per top-level statement and defers `free_statement` until a new statement begins, so multi-triple fan-out stays valid while drained.
- **Prefix map**: keys AND values interned (`intern(prefix)` as key) — simplest way to keep keys valid across statements.
- **All four directive forms** work; later `@prefix` overrides (map assignment); `parser_init` takes an optional `base` parameter (needed by the W3C eval harness, which supplies the manifest base); relative initial base errors at init.
- **Blank-node scheme locked in**: synthesized labels are `b<n>` (deterministic counter, interned); document labels matching `^B*b[0-9]+$` get one `'B'` prepended (injective, streaming-safe, O(1) test). All other document labels preserved byte-for-byte. `<<` `>>` reified/annotation/number tokens error until their tasks land.
- `iri_ref_term` unescapes UCHARs into scratch (not per-statement owned — the resolver copies), so escaped IRIs cost no per-statement allocation.
- One scanner/parser boundary note: `@prefix ex <iri>` (missing colon) surfaces as the scanner's `Unknown_Keyword`, not `Expected_Prefix_Name` — correct position, documented in the test.
