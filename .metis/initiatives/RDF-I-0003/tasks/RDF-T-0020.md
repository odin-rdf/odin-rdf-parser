# Replace harness manifest reader with the Turtle parser

## Parent Initiative

[[RDF-I-0003]]

## Objective

Replace the hand-rolled manifest reader in `tests/w3c/harness` with the real Turtle parser, retiring the technical debt recorded in RDF-T-0010 — the dogfooding milestone where the harness that validates the parsers runs on one of them.

## Acceptance Criteria

## Acceptance Criteria

- [ ] Manifest loading in `tests/w3c/harness` uses `rdf/turtle`; the hand-rolled reader is deleted, not deprecated.
- [ ] All previously passing suites still pass with identical test counts: the 213 line-based tests plus the [[RDF-T-0019]] Turtle/TriG suites.
- [ ] Manifest constructs the hand-rolled reader special-cased (`mf:entries` collections, `rdf:type` filtering, prefixed names) are handled by real parsing plus graph queries over the result.
- [ ] Any manifest construct the hand-rolled reader silently tolerated but the real parser rejects is investigated and documented in Status Updates (this is the debt made visible).
- [ ] Harness-internal tests (if any) updated; no test-behavior change beyond the reader swap.

## Implementation Notes

### Technical Approach

Parse each `manifest.ttl` into an in-memory statement list, then query it (subject lookup, `mf:entries` list walk) with small helpers. The RDF-T-0010 debt notes describe what the hand-rolled reader assumed — read them first and diff those assumptions against real parses of every vendored manifest before deleting anything.

### Dependencies

[[RDF-T-0015]] technically suffices (manifests need prefixed names and collections), but sequenced after [[RDF-T-0019]] so suite bring-up never depends on the parser it is validating.

### Risk Considerations

Circularity: a Turtle parser bug could silently drop manifest entries and mask conformance failures. Mitigate by asserting the per-suite entry counts recorded in [[RDF-T-0019]]'s Status Updates stay identical across the swap.
