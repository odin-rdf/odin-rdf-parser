# N-Triples parser

## Parent Initiative

[[RDF-I-0002]]

## Objective

Implement the N-Triples parser in package `rdf/triples`: the resolved scanner-idiom API over the internal tokenizer, yielding borrowed `rdf.Triple` statements with copy-on-write unescaping.

## Acceptance Criteria

- [ ] `Parser` with `parser_init(p, source: []byte, allocator := context.allocator)`, `parser_next(p) -> (rdf.Triple, bool)`, `parser_destroy(p)`; after a `false` return, `p.err` distinguishes clean EOF from a syntax error.
- [ ] Conforms to the W3C RDF 1.2 N-Triples grammar, including triple terms (`<<( ... )>>`, object position only, nesting supported).
- [ ] Escape handling: ECHAR and UCHAR unescaping applied only to tokens whose `has_escape` flag is set, allocated from the parser's allocator and released by `parser_destroy`; statements without escapes allocate nothing (tracking-allocator test).
- [ ] Errors use the shared `Error` struct (kind, offset, line, column) and a formatting proc references the violated grammar production; errors are sticky — after a syntax error, `parser_next` keeps returning `false` and parser state stays valid for reading `p.err`.
- [ ] Statement validity contract documented on `parser_next`: yielded triples are valid until the next call or `parser_destroy` (per ADR RDF-A-0001); callers keep statements via `rdf.clone` or an `Intern_Table`.
- [ ] Unit tests: representative valid documents (all term kinds, escapes, triple terms, comments, blank/whitespace lines), malformed inputs per error kind with expected positions, zero-allocation check; `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
The statement-level parsing (subject/predicate/object/term recognition) should be written for reuse — N-Quads (RDF-T-0008) adds only the optional graph label, so this logic lands in the internal package or a form the quads package can call, not copy.

Sticky-error semantics chosen over skip-to-next-line recovery: simplest correct contract, and the W3C negative-syntax tests only need "document rejected". Line-level recovery can be added later without breaking the API.

### Dependencies
RDF-T-0006 (internal scanner).
