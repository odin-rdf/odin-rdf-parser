# Internal scanner package for line-based formats

## Parent Initiative

[[RDF-I-0002]]

## Objective

Build the shared tokenizer for the line-based formats as an internal package (`rdf/internal/scanner`), producing borrowed-slice tokens over a caller-owned `[]byte` per ADR RDF-A-0001.

## Acceptance Criteria

## Acceptance Criteria

- [x] Tokens for the RDF 1.2 N-Triples/N-Quads grammars: IRIREF, STRING_LITERAL_QUOTED, BLANK_NODE_LABEL, LANGTAG (including the RDF 1.2 `--ltr`/`--rtl` direction suffix), `^^`, `.`, the RDF-star triple-term delimiters `<<(` and `)>>`, with comments and whitespace skipped and end-of-line/end-of-input reported.
- [x] Token values are borrowed slices into the source buffer; each token carries a `has_escape` flag set during scanning (no lookahead re-scan), plus byte offset, line, and column.
- [x] Scanner errors carry the `Error_Kind`/position structure resolved in the initiative design; an invalid character fails with a precise position.
- [x] Scanning allocates nothing, for any input (verified with a tracking allocator in tests).
- [x] Unit tests cover every token kind, positive and negative, including escape-flag detection and position reporting; `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
Odin has no enforced package privacy, so "internal" is by path convention (`rdf/internal/`) and documentation. The scanner is byte-oriented over `[]byte`; UTF-8 validation happens only where the grammar requires it. The Error type likely lives here and is re-exported/aliased by the format packages so both share one definition.

### Dependencies
None within this initiative (core model from RDF-I-0001 is complete).

## Status Updates

**2026-08-04**: Implemented in `rdf/internal/scanner/` (`token.odin`, `error.odin`, `scanner.odin`, `scanner_test.odin`). API mirrors the resolved parser idiom one level down: `scanner_init(&s, source)`, `scanner_next(&s) -> (Token, bool)`, with `s.err` distinguishing clean EOF from an error. Decisions made during implementation, to be validated against the W3C suite in RDF-T-0010:

- **Newlines are inter-token whitespace** (tracked for line/column) rather than emitted as EOL tokens. The strict grammar separates triples with EOL; if a W3C negative test requires rejecting statements that span lines, enforcement will be added in the parsers using token line numbers — the scanner API already carries what's needed.
- **Blank-node labels validate ASCII strictly but accept any byte ≥ 0x80 loosely** instead of checking exact PN_CHARS Unicode ranges. Tighten if the suite has counterexamples.
- **Dot disambiguation in labels**: `.` is consumed into a label only when followed by another label character, so `_:b1.` tokenizes as label `b1` + Dot without lookbehind.
- **UCHAR hex digits validated during scanning** (`\uXXXX`/`\UXXXXXXXX`), so the parsers' unescaping can assume well-formed escapes.
- **Error messages reference grammar productions by name** (IRIREF, STRING_LITERAL_QUOTED, …) rather than number — production numbers shift between spec revisions, names don't. Parser-level Error_Kinds are co-located here so both format packages share one Error type.

Tests: 8/8 green (statement tokenization, delimiter stripping, escape-flag detection, label/dot boundary, line/column positions, 14 negative cases, error position accuracy, zero-allocation guard); `odin check -vet -strict-style` clean; core `rdf` package unaffected (15/15). Task complete.
