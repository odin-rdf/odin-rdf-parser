# Internal scanner package for line-based formats

## Parent Initiative

[[RDF-I-0002]]

## Objective

Build the shared tokenizer for the line-based formats as an internal package (`rdf/internal/scanner`), producing borrowed-slice tokens over a caller-owned `[]byte` per ADR RDF-A-0001.

## Acceptance Criteria

- [ ] Tokens for the RDF 1.2 N-Triples/N-Quads grammars: IRIREF, STRING_LITERAL_QUOTED, BLANK_NODE_LABEL, LANGTAG (including the RDF 1.2 `--ltr`/`--rtl` direction suffix), `^^`, `.`, the RDF-star triple-term delimiters `<<(` and `)>>`, with comments and whitespace skipped and end-of-line/end-of-input reported.
- [ ] Token values are borrowed slices into the source buffer; each token carries a `has_escape` flag set during scanning (no lookahead re-scan), plus byte offset, line, and column.
- [ ] Scanner errors carry the `Error_Kind`/position structure resolved in the initiative design; an invalid character fails with a precise position.
- [ ] Scanning allocates nothing, for any input (verified with a tracking allocator in tests).
- [ ] Unit tests cover every token kind, positive and negative, including escape-flag detection and position reporting; `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
Odin has no enforced package privacy, so "internal" is by path convention (`rdf/internal/`) and documentation. The scanner is byte-oriented over `[]byte`; UTF-8 validation happens only where the grammar requires it. The Error type likely lives here and is re-exported/aliased by the format packages so both share one definition.

### Dependencies
None within this initiative (core model from RDF-I-0001 is complete).
