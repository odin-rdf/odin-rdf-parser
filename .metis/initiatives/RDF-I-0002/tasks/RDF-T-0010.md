# W3C test-suite harness and vendored suites

## Parent Initiative

[[RDF-I-0002]]

## Objective

Vendor the official W3C N-Triples and N-Quads test suites and build the manifest-driven conformance harness that runs them, designed for reuse by the later Turtle/TriG initiative.

## Acceptance Criteria

## Acceptance Criteria

- [x] Official RDF 1.2 N-Triples and N-Quads suites vendored under `tests/w3c/`, with a README recording the source URL, upstream commit/version, and retrieval date.
- [x] Manifest reader parses the `manifest.ttl` files' restricted Turtle subset (see note below) into test-case records: id, type (positive/negative syntax), input file, name.
- [x] Runner executes every test in both manifests through the real parsers: positive-syntax documents must parse without error; negative-syntax documents must be rejected. RDF-star cases included.
- [x] Failures report the W3C test id and, for wrongly-rejected documents, the parser's formatted error; the suite runs under `odin test` with no network access.
- [x] Both suites pass 100% (this is the initiative's conformance gate); `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
**Manifest chicken-and-egg, decided here**: W3C manifests are Turtle files, but this project has no Turtle parser yet. The harness includes a minimal, hand-rolled reader for the tiny Turtle subset the manifests actually use (prefixes, one collection, simple predicate-object lists). It is test infrastructure, not a public Turtle parser — it lives under `tests/`, is documented as such, and gets replaced by the real Turtle parser when that initiative lands.

The harness core (manifest model + runner) should be format-agnostic so Turtle/TriG plug in later with only a new parser adapter.

### Dependencies
RDF-T-0007 and RDF-T-0008 (the parsers under test).

## Status Updates

**2026-08-04**: **All 213 conformance tests pass (100%)** across four vendored suites: rdf11-ntriples (70), rdf11-nquads (87), rdf12-ntriples-syntax (29), rdf12-nquads-syntax (27). Suites vendored from w3c/rdf-tests @ `767554e135eb6665949d870e6fa7bbc813837293` (retrieved 2026-08-04, provenance in `tests/w3c/README.md`). Scope note: the upstream README states RDF 1.2 conformance = RDF 1.2 suites *plus* the RDF 1.1 suites, so all four are vendored — more than the task's literal "both manifests". The `c14n/` canonicalization suites are excluded (out of scope for syntax conformance).

Harness in `tests/w3c/harness` (package `w3c`): line-oriented manifest reader producing id/name/type/action records, format-agnostic runner (`Format` enum selects the parser), unknown test types fail loudly rather than being skipped, and paths resolve via `#directory` so `odin test tests/w3c/harness` works from anywhere with no network.

**The first run found three real conformance bugs (200/213), all fixed:**
1. **Relative IRIs were accepted** — added a scheme check (`alpha (alnum|+|-|.)* :`) in `statement.iri_term`, applied to every IRI position including graph labels and datatypes; new `Relative_IRI` error kind. (nt-syntax-bad-uri-06..09, nq-syntax-bad-uri-01, ntriples12-bad-iri-1)
2. **`"x"^^rdf:langString` / `^^rdf:dirLangString` were accepted** — RDF 1.2 reserves these datatypes for language-tag syntax, disproving the RDF 1.1-era "syntactically legal though ill-typed" assumption recorded in RDF-T-0007; new `Reserved_Datatype` error kind. (ntriples-langdir-bad-3/-5)
3. **Over-long language subtags were accepted** — scanner now enforces BCP47 well-formedness at the subtag-length level (1–8 chars). (ntriples-langdir-bad-4)

The scanner decisions flagged in RDF-T-0006 (newlines as whitespace, loose non-ASCII blank-node labels) survived the full suites — no counterexamples. Full test suite 46/46 plus 213 conformance; all packages `-vet -strict-style` clean.
