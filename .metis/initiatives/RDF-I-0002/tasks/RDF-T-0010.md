# W3C test-suite harness and vendored suites

## Parent Initiative

[[RDF-I-0002]]

## Objective

Vendor the official W3C N-Triples and N-Quads test suites and build the manifest-driven conformance harness that runs them, designed for reuse by the later Turtle/TriG initiative.

## Acceptance Criteria

- [ ] Official RDF 1.2 N-Triples and N-Quads suites vendored under `tests/w3c/`, with a README recording the source URL, upstream commit/version, and retrieval date.
- [ ] Manifest reader parses the `manifest.ttl` files' restricted Turtle subset (see note below) into test-case records: id, type (positive/negative syntax), input file, name.
- [ ] Runner executes every test in both manifests through the real parsers: positive-syntax documents must parse without error; negative-syntax documents must be rejected. RDF-star cases included.
- [ ] Failures report the W3C test id and, for wrongly-rejected documents, the parser's formatted error; the suite runs under `odin test` with no network access.
- [ ] Both suites pass 100% (this is the initiative's conformance gate); `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
**Manifest chicken-and-egg, decided here**: W3C manifests are Turtle files, but this project has no Turtle parser yet. The harness includes a minimal, hand-rolled reader for the tiny Turtle subset the manifests actually use (prefixes, one collection, simple predicate-object lists). It is test infrastructure, not a public Turtle parser — it lives under `tests/`, is documented as such, and gets replaced by the real Turtle parser when that initiative lands.

The harness core (manifest model + runner) should be format-agnostic so Turtle/TriG plug in later with only a new parser adapter.

### Dependencies
RDF-T-0007 and RDF-T-0008 (the parsers under test).
