# N-Triples and N-Quads emitters with round-trip tests

## Parent Initiative

[[RDF-I-0002]]

## Objective

Implement spec-valid N-Triples and N-Quads emitters writing to `io.Writer`, with escaping as the exact inverse of the parsers' unescaping, proven by round-trip tests.

## Acceptance Criteria

- [ ] `emit` procedures in both packages writing a single statement (plus a document-level convenience for a slice of statements) to `core:io`'s `io.Writer`, propagating `io.Error`.
- [ ] Output conforms to the RDF 1.2 grammars: minimal mandatory escaping (`\"`, `\\`, `\n`, `\r`, other control characters via `\u`), language tags with direction suffixes, triple terms as `<<( ... )>>`, blank nodes with the `_:` prefix restored, `nil` graph label emitting no label.
- [ ] Emitters perform no allocation (writes go straight to the writer; tracking-allocator test).
- [ ] Round-trip property: parse → emit → parse yields statements `rdf.equal` to the originals, for a corpus covering all term kinds, escapes, direction suffixes, nested triple terms, and all three graph-label cases.
- [ ] `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
The character-level emission (terms, escaping) is shared between the two packages via the internal package, mirroring the parser side. Escaping tables should be derived from the same spec productions the scanner validates against, so parser and emitter can't drift apart.

### Dependencies
RDF-T-0007 and RDF-T-0008 (round-trip tests need both parsers).
