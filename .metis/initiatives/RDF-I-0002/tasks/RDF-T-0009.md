# N-Triples and N-Quads emitters with round-trip tests

## Parent Initiative

[[RDF-I-0002]]

## Objective

Implement spec-valid N-Triples and N-Quads emitters writing to `io.Writer`, with escaping as the exact inverse of the parsers' unescaping, proven by round-trip tests.

## Acceptance Criteria

## Acceptance Criteria

- [x] `emit` procedures in both packages writing a single statement (plus a document-level convenience for a slice of statements) to `core:io`'s `io.Writer`, propagating `io.Error`.
- [x] Output conforms to the RDF 1.2 grammars: minimal mandatory escaping (`\"`, `\\`, `\n`, `\r`, other control characters via `\u`), language tags with direction suffixes, triple terms as `<<( ... )>>`, blank nodes with the `_:` prefix restored, `nil` graph label emitting no label.
- [x] Emitters perform no allocation (writes go straight to the writer; tracking-allocator test).
- [x] Round-trip property: parse → emit → parse yields statements `rdf.equal` to the originals, for a corpus covering all term kinds, escapes, direction suffixes, nested triple terms, and all three graph-label cases.
- [x] `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
The character-level emission (terms, escaping) is shared between the two packages via the internal package, mirroring the parser side. Escaping tables should be derived from the same spec productions the scanner validates against, so parser and emitter can't drift apart.

### Dependencies
RDF-T-0007 and RDF-T-0008 (round-trip tests need both parsers).

## Status Updates

**2026-08-04**: Character-level emission lives in `rdf/internal/emit` (term serialization, IRI escaping, string escaping, graph labels); `rdf/triples` and `rdf/quads` add thin `emit`/`emit_all` procs that frame statements (" .\n", optional graph label). Decisions:

- **Canonical-leaning output**: `xsd:string` datatype is implicit (omitted); an empty datatype on hand-built literals is treated as plain rather than emitting `^^<>`.
- **Escaping**: named ECHARs (`\" \\ \n \r \t \b \f`), remaining control chars as `\u00XX`; IRIs defensively escape the IRIREF-forbidden set so output is grammatically valid even for questionable hand-built terms.
- **Chunked writes**: escaping scans for the next byte needing an escape and writes raw runs in between — no per-byte writer calls on clean content, no allocation anywhere (tracking-allocator verified with a nested-triple-term, escaped, directional statement).
- Emitting a nil `Term` writes nothing (documented as caller responsibility).

Tests: exact-output checks (escapes, direction suffix, implicit vs explicit datatype, all three graph-label framings) and parse → emit → parse round trips over corpora covering every term kind, escapes, direction suffixes, two-level nested triple terms, and all graph-label cases — statements compare `rdf.equal`. Full suite 42/42; `-vet -strict-style` clean. Task complete.
