# Zero-copy benchmarks and allocation guards

## Parent Initiative

[[RDF-I-0002]]

## Objective

Guard the zero-copy promise with allocation-count tests and throughput benchmarks, so an accidental copy in a future change fails loudly instead of regressing silently.

## Acceptance Criteria

- [ ] Guard tests (run under `odin test`) assert **zero allocations** when parsing a generated escape-free corpus with both parsers, and the expected exact allocation count for an escape-bearing corpus (one unescape per flagged token).
- [ ] Throughput benchmark (statements/second and MB/s) for both parsers and both emitters over generated corpora of meaningful size (≥ 100k statements), runnable via a documented command.
- [ ] Corpus generator is deterministic (seeded) so numbers are comparable across runs and machines-of-the-same-kind.
- [ ] Baseline numbers on the development machine recorded in this task's Status Updates for future comparison.
- [ ] `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
Allocation guards use `mem.Tracking_Allocator` as the parser allocator — the same technique as the data-model tests. Benchmarks live outside the test suite proper (e.g., `bench/` with a small main), since `odin test` timing is not a benchmark harness; only the allocation guards gate CI.

### Dependencies
RDF-T-0007 and RDF-T-0008 (parsers; emitter benchmarks also use RDF-T-0009 but the task can start on parser guards before emitters land).
