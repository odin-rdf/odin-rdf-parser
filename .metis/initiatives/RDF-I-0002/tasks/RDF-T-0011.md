# Zero-copy benchmarks and allocation guards

## Parent Initiative

[[RDF-I-0002]]

## Objective

Guard the zero-copy promise with allocation-count tests and throughput benchmarks, so an accidental copy in a future change fails loudly instead of regressing silently.

## Acceptance Criteria

## Acceptance Criteria

- [x] Guard tests (run under `odin test`) assert **zero allocations** when parsing a generated escape-free corpus with both parsers, and the expected exact allocation count for an escape-bearing corpus (one unescape per flagged token).
- [x] Throughput benchmark (statements/second and MB/s) for both parsers and both emitters over generated corpora of meaningful size (≥ 100k statements), runnable via a documented command.
- [x] Corpus generator is deterministic (seeded) so numbers are comparable across runs and machines-of-the-same-kind.
- [x] Baseline numbers on the development machine recorded in this task's Status Updates for future comparison.
- [x] `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
Allocation guards use `mem.Tracking_Allocator` as the parser allocator — the same technique as the data-model tests. Benchmarks live outside the test suite proper (e.g., `bench/` with a small main), since `odin test` timing is not a benchmark harness; only the allocation guards gate CI.

### Dependencies
RDF-T-0007 and RDF-T-0008 (parsers; emitter benchmarks also use RDF-T-0009 but the task can start on parser guards before emitters land).

## Status Updates

**2026-08-04**: Implemented as `bench/corpus` (deterministic generator — output is a pure function of arguments, cycling term shapes and graph-label cases), `tests/guards` (CI-gating allocation guards under `odin test`), and `bench/` (throughput benchmarks, `odin run bench -o:speed`).

Guards over 10k-statement corpora: **zero** total allocations for escape-free parsing in both formats, and **exactly** N+1 allocations for the all-escaped corpus (one unescape buffer per escaped token plus the parser's owned-list backing, reused across statements) with a leak-free destroy. The exact-count form is deliberately strict — any accidental copy changes the count and fails.

**Baseline (Apple Silicon dev machine, Odin dev-2026-07, -o:speed, 200k statements):**
- N-Triples parse (escape-free): ~10.7M stmts/s, ~1016 MB/s
- N-Triples parse (escaped): ~8.5M stmts/s, ~772 MB/s
- N-Quads parse (escape-free): ~11.3M stmts/s, ~1132 MB/s
- N-Triples emit: ~7.8M stmts/s, ~747 MB/s
- N-Quads emit: ~7.3M stmts/s, ~732 MB/s

All packages `-vet -strict-style` clean. Task complete — and with it every task of RDF-I-0002.
