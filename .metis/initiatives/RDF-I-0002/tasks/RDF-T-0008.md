# N-Quads parser

## Parent Initiative

[[RDF-I-0002]]

## Objective

Implement the N-Quads parser in package `rdf/quads`: the same API and semantics as `rdf/triples`, extended with the optional graph label, yielding borrowed `rdf.Quad` statements.

## Acceptance Criteria

- [ ] Same API shape as `rdf/triples` with `parser_next(p) -> (rdf.Quad, bool)`; identical error and lifetime contracts.
- [ ] Conforms to the W3C RDF 1.2 N-Quads grammar: optional graph label (IRI or blank node) before the terminating dot; absent label yields a `nil` `Graph_Label` (default graph).
- [ ] Statement parsing is shared with `rdf/triples` through the internal package — the graph-label extension is the only quads-specific grammar code, no copy-pasted term parsing.
- [ ] Zero allocation for escape-free statements, including ones with graph labels (tracking-allocator test).
- [ ] Unit tests: quads with IRI graph labels, blank-node graph labels, and no label; malformed graph-label cases (e.g., a literal as label) with expected error kinds and positions; `odin check -vet -strict-style` clean.

## Implementation Notes

### Technical Approach
By this point the shared statement core exists (factored in RDF-T-0007); this task is the thin quads layer plus its test matrix. If the factoring turns out wrong for the graph-label extension, fix it here rather than duplicating.

### Dependencies
RDF-T-0007 (shared statement-parsing core is factored during the N-Triples parser).
