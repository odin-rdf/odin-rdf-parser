# API documentation for all public packages

## Objective

Document the public API of every exported package — `rdf` (core model), `rdf/triples`, `rdf/quads`, `rdf/turtle`, `rdf/trig` — with doc comments, so downstream projects (first: `odin-rdf-sparql`) can build on the library without reading its internals. RDF-T-0005 documented the core model; the four parser/emitter packages have no API documentation, and the ownership/lifetime contracts live only in ADR RDF-A-0001 and initiative design notes.

## Backlog Item Details

### Type
- [x] Tech Debt - Code improvement or refactoring

### Priority
- [x] P1 - High (important for user experience)

### Technical Debt Impact
- **Current Problems**: The contracts that matter most to a consumer — which slices are borrowed from the source buffer, what the intern table owns and for how long, what `parser_destroy` frees, per-statement validity — are recorded in Metis documents, not at the API surface where users will look.
- **Benefits of Fixing**: A SPARQL engine can hold terms beyond the parser's lifetime correctly (clone/intern) on the first try; closes the vision's "public API is documented and idiomatic Odin" success criterion together with [[RDF-T-0022]].
- **Risk Assessment**: The failure mode of an undocumented borrowing contract is use-after-free in downstream code — subtle, and expensive to debug there.

## Acceptance Criteria

## Acceptance Criteria

- [x] Package-level doc comment for each of the five public packages describing its role and pointing to its siblings.
- [x] Every public type and proc has a doc comment: parser lifecycle (`parser_init` / `parser_next` / `parser_destroy`), emitter lifecycle (`emitter_init` / `emit` / `emitter_finish` / `emitter_destroy`), error types, prefix types, and the core-model procs added since RDF-T-0005.
- [x] Ownership and lifetime contract documented where it bites: borrowed slices vs. copy-on-write unescapes, intern-table ownership of expanded/resolved IRIs, per-statement validity, and how to retain terms beyond parser lifetime (clone/intern from RDF-T-0003).
- [x] Error model documented: sticky `p.err`, `Error` struct fields, matching on `Error_Kind`, the message-formatting proc.
- [x] Emitter contracts documented: `io.Writer` output, escaping guarantees, prefix-map behavior including the empty-map (flat output) case.
- [x] `odin doc` output spot-checked for each package — no missing or garbled entries.

## Implementation Notes

### Technical Approach
This is transcription, not design: the contracts are already decided in ADRs RDF-A-0001/0002 and the initiative design sections — move them to where users will see them. Follow the doc style of Odin core packages the APIs already imitate (`core:bufio` for the scanner idiom, `core:encoding/json` for the writer idiom).

### Dependencies
None. [[RDF-T-0022]] (README) should link here rather than duplicate contract detail; if [[RDF-T-0024]] lands first, its documented buffering contract belongs in these package docs too.

## Status Updates

**2026-08-04 — Completed (commit 464a0fc).**

Survey found the packages already substantially documented by the parser initiatives; the task closed the remaining gaps rather than starting from zero:

- Added doc comments to the undocumented lifecycle procs: `parser_init`/`parser_destroy` in `rdf/triples` and `rdf/quads`, `parser_destroy` in `rdf/turtle` and `rdf/trig`, `emitter_destroy` in both Turtle-family emitters.
- Stated the RDF-T-0024 whole-document-in-buffer contract in all four format packages' docs, with mmap named for large files, plus the source-must-stay-valid-and-unmoved requirement on `parser_init`.
- Documented a previously unstated borrow: the Turtle/TriG emitters borrow the caller's `Prefix` slice, which must outlive the emitter (verified in `rdf/internal/ttl/emitter.odin` — the slice is stored, not copied).
- Added sibling-package cross-references to all five package docs.
- Fixed turtle/trig package docs claiming "parses" only — both also emit.
- Verified: `odin doc` renders cleanly for all five packages; all tests pass (15 model, 5 guards, 10 W3C suite runners covering the 1045 conformance entries).

Error model, escaping guarantees, and the clone/intern promotion path were already documented from RDF-T-0005/0009/0018 and needed no changes.
